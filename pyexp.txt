2. HOW I APPROACHED THIS (MY ENGINEERING METHODOLOGY)
--------------------------------------------------------------------------------
I took a structured, bottom-up engineering approach:

Step 1: Analyzed the Contract with Teammates First
  - Member 2 (Tracer) needs to hand off execution data at every line hit without 
    knowing anything about SQL or database connections.
  - Member 1 (TUI) needs to slide a timeline backward and forward, inspect 
    variables, and query single-variable histories ("Watch Variables").

Step 2: Database Schema Selection (Normalized Key-Value vs. JSON Blobs)
  - I evaluated two designs:
      Design A: Storing an entire dictionary as an opaque JSON blob per event.
      Design B: A normalized schema separating `trace_events` from `variable_states`.
  - I chose Design B (Normalized Key-Value). Why?
      1. Directly fulfills the spec: (timestamp, line_number, variable_name, serialized_value).
      2. Allows indexed SQL queries for the TUI "Watch Variable" feature.
      3. Seamlessly absorbs Week 3 Delta Compression: when only 1 variable mutates, 
         we insert only 1 row in `variable_states` rather than duplicating the entire 
         state dictionary.

Step 3: Safe Serialization Before Storage
  - SQLite cannot store raw Python memory objects. Standard `pickle` is dangerous 
    (security risks) and fragile.
  - I built a custom, cycle-safe JSON serializer with recursive sanitization, 
    automatic truncation, and graceful fallbacks for unpicklable objects (files, 
    sockets, functions, lambdas).

Step 4: Built a High-Level StorageManager Facade
  - Wrapped all raw SQL operations inside `StorageManager`. Teammates call simple 
    Python methods like `start_execution()`, `record_event()`, and `get_events()`.

Step 5: Verified with Mock Tracer & Automated Tests
  - Created a fake event generator (`mock_tracer.py`) so I could test the entire 
    pipeline end-to-end independently, without waiting for teammates to finish 
    their modules.

3. WHAT TECHNOLOGIES & CONCEPTS I USED
--------------------------------------------------------------------------------
1. Python Standard Library:
   - `sqlite3`: Fast, embedded relational database (zero external server needed).
   - `dataclasses`: Clean, type-safe data modeling (`ExecutionRecord`, `TraceEvent`).
   - `json`: Lightweight, portable serialization.
   - `time` & `tempfile`: Precision benchmarking and isolated temporary testing.

2. SQLite Database Optimizations:
   - `PRAGMA foreign_keys = ON;`: Enforces relational integrity across tables.
   - `PRAGMA journal_mode = WAL;`: Write-Ahead Logging allows the TUI to read 
     execution history while the tracer writes without locking the database.
   - `PRAGMA synchronous = NORMAL;`: Optimizes disk sync latency.
   - Parameterized SQL (`?` placeholders): Prevents SQL injection and allows 
     SQLite's query planner to pre-compile execution statements.

3. Algorithm & Architectural Patterns:
   - Solved the N+1 Query Problem: Instead of querying variables in a loop per 
     event, `get_events_for_execution()` fetches all related variable rows in a 
     single batch `WHERE event_id IN (...)` query.
   - Cycle Detection via Memory IDs: Prevents infinite recursion on circular 
     references (e.g. `a = [a]`) using `id(obj)` tracking.
   - Monotonic Sequence Numbers: Enforces strict chronological order 
     (`UNIQUE(execution_id, sequence)`), eliminating bugs caused by clock drift 
     or microsecond timestamp collisions.

6. ANSWERS TO LIKELY QUESTIONS FROM YOUR TEAM LEAD
--------------------------------------------------------------------------------
Q: "Why did you use SQLite instead of storing JSON files?"
A: SQLite provides ACID transactions, indexing on `(execution_id, sequence)`, 
   and WAL mode for concurrent read/write. It allows the TUI to run instant, 
   indexed lookups (like querying a single variable or a slice of lines) without 
   loading gigabytes of JSON into memory.

Q: "Why not just use Python's built-in `pickle` for serialization?"
A: Pickle is unsafe (can execute arbitrary code upon unpickling), brittle across 
   Python versions, and cannot be inspected by external tools or SQLite GUIs. 
   Our JSON serializer with safe repr fallbacks is secure, inspectable, and 
   never crashes if an object has an open file handle or socket.

Q: "How do you guarantee ordering if two lines run in the same microsecond?"
A: We do not rely on timestamps for ordering. Every event is assigned a strictly 
   monotonic `sequence` integer (1, 2, 3...) per execution, enforced by a 
   `UNIQUE(execution_id, sequence)` constraint in SQLite.

Q: "How will Week 3 Delta Compression fit in without rewriting this?"
A: We already included the `is_delta` flag in `trace_events`. In Week 3, the 
   storage manager will compute state diffs and only insert rows into 
   `variable_states` for variables that actually changed on that line. 
   The database schema requires ZERO modifications.
