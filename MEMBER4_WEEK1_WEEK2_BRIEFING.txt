2. Architecture & How it Works
--------------------------------------------------------------------------------
The UI is built with a clear separation of concerns across widgets:

- Layout:
  * Left pane (58% width): Displays target Python source code with syntax 
    highlighting (Monokai theme) and an active line highlight.
  * Right pane (42% width): Displays the variable state table for the active step.
  * Bottom dock: Timeline slider showing current step, total steps, and playback 
    buttons.

- State Flow:
  1. The app loads execution events from `StorageManager.get_events()`.
  2. When the user scrubs the timeline (using arrow keys or buttons), the timeline 
     emits a `StepChanged` message.
  3. The main app receives the message and updates both the code viewer (to highlight 
     the line) and the variable viewer (to show the variable snapshot at that step).
  4. If a variable changed from the previous line, the variable viewer marks it 
     with `MOD` and displays the old vs new value (`was 0 -> 10`).

- Auto-Scroll Engine:
  To prevent the active line from moving off-screen in long scripts, `CodeViewer` 
  calculates scroll offsets (`scroll_to(y=active_line - 5)`) so the highlighted line 
  stays centered in the terminal window.

- Safe Fallback:
  If a target script file cannot be found on disk, the code viewer displays a clean 
  informational placeholder rather than crashing.

--------------------------------------------------------------------------------
3. Integration with Member 3 (Storage Engine)
--------------------------------------------------------------------------------
The UI connects directly to Member 3's `StorageManager` without running raw SQL:
- Reads `TraceEvent` objects returned by `storage.get_events(execution_id)`.
- Extracts `event.line_number` to highlight lines in `CodeViewer`.
- Extracts `event.state` to populate `VariableViewer`.
- Extracts `event.sequence` to synchronize the timeline slider.

This ensures the UI remains completely decoupled from database schema internals.

5. How to Run and Test
--------------------------------------------------------------------------------
Run the interactive demo:
    python demo_week1_week2_tui.py

Run against a specific SQLite database:
    python run_tui.py --db trace.db

Run the automated test suite:
    pytest -v tests/
